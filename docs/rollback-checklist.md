# Change and rollback checklist (public summary)

- Record the reason for the change and the test revision.
- Confirm that the change was tested in a separate environment.
- Agree on a maintenance window and a responsible reviewer.
- Verify that an appropriate backup and restore process exists.
- Document a safe rollback decision point.
- Communicate any player-visible downtime.

This is a high-level community transparency document, not an operational runbook. No access instructions, credentials, endpoints, or backup locations are included.
